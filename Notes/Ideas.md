## Etude Generator

The main ideas here are:

- This is a web application, with full user authentication and session management
- Users must sign in to use the application
- I want to generate music for the piano as a student; there is no separate teacher interface
- The user should be able to select a number of parameters for the music generation
  - Number of measures
  - Time signature
- The music should be generated from a list of:
  - Notes (e.g., "A", "A#/Bb", "B", "C", "C#/Db", "D", etc., and "Rest")
  - Durations (e.g., 1/4, 1/2, 1, dotted half, dotted quarter, etc.)
  - One or more octaves (e.g., 4, 5, 6)
  - Hand (left, right, both)
- The music should then be generated randomly from the list of notes, durations, octaves, and hand(s) selected
  - The music should not be totally random:
    - There should be repeated phrases
      - For example, a 4-measure phrase that repeats twice, or a 3-note sequence that repeats three times
      - Probabilities of intervals in half-steps: (which sum to 1.0)
        - 0: 0.0932197441181743
        - 1: 0.0755079927357212
        - 2: 0.121143267210103
        - 3: 0.109028940489093
        - 4: 0.0981260464401835
        - 5: 0.0883134417961651
        - 6: 0.0794820976165486
        - 7: 0.0715338878548937
        - 8: 0.0643804990694044
        - 9: 0.0579424491624639
        - 10: 0.0521482042462175
        - 11: 0.0469333838215958
        - 12: 0.0422400454394362
    - For each hand, note durations in a bar should sum properly to the number of beats in the bar
      - For example, in 4/4 time, a bar should have 4 beats total
      - When two hands are generated, they should be different notes, with the lower note assigned to the left hand and the higher note assigned to the right hand
      - There is a fifty-fifty probability, for any individual bar, that notes generated for each hand are independent of each other or of the same durations (but different pitches)
      - Initial octaves should be chosen randomly from the available octaves
      - Jumps over an octave should not be generated
  - Each bar for each hand should be generated in the following way:
    - Start with a single note from the user's range, that fills the entire bar (e.g., whole note for 4/4 time), in one of the user's selected octaves
    - Loop:
      - Randomly pick a note in the bar and split the note into smaller notes, following the duration probabilities above, with the constraint that the sum of the durations of the smaller notes equals the duration of the original note
      - With a probability of 0.1, make a note a rest
      - Continue the loop until:
        - The bar only contains note durations allowed by the user
        - When there are only allowed durations, but there are still notes which could be split to shorter allowed durations, randomly decide whether to continue splitting or stop
    - If both hands need to be generated:
      - When the choice is same rhythm for the second hand, ensure that the notes chosen for the second hand are not the same pitch as the first hand
      - When the choice is independent rhythm for the second hand, redo the splitting algorithm again, and ensure that the notes chosen for the second hand are not the same pitch as the first hand at the same moment in time
- The music should be stored internally in a presentation-independent way.
- The generated music should:
  - Have sheet music style images generated by lilypond (https://lilypond.org) using the current stable release
    - Notes played by the right hand should have stems pointing up
    - Notes played by the left hand should have stems pointing down
    - The lilypond web application is a separate web application, accessed via HTTP POST with a JSON body containing the LilyPond code, and a Bearer token for authentication. It should return an SVG of the sheet music and a MIDI string of the same notes by default.
    - There should be a button on the page, once a piece is created, to regenerate it via the lilypond web application as a PDF only for download
  - Have MIDI generated in a way that can be played by the browser when a button is clicked
    - Using the Tone.js library (https://tonejs.github.io)
    - Using their Sampler synthesizer with the 'salamander' library
- There should be a form with all the note generation parameters at the top of the page
- There should be a "Generate" button on the form that will generate the music and display it below the form
- The form should have the same values it had before the POST once the music is generated
- There should be audio control buttons that will only appear once music is generated, that will control playback
  - The audio controls should include stop and play, and a slider to adjust the beats per minute (between 40 and 200)

### Data structures

- The internal music representation should be a JSON-serializable hierarchical structure: Piece → Measures → Notes.
  - Piece contains an array of measures.
  - Each measure contains one or two arrays of notes (one for right hand, one for left hand). If there is only one hand being generated, the left hand array should have notes, the right hand array should be empty.
  - Each note has: pitch and duration info.

Changes from base auth app:

### Content Security Policy

- New etude-page specific CSP configuration created (not reusing `ALLOW_SCRIPTS_SECURE_HEADERS`).
- CSP allows `allow-same-origin`, `allow-scripts`, `allow-forms` in sandbox.
- `scriptSrc` includes `'self'` only (Tone.js bundled locally in `public/`).
- Tone.js is downloaded and served from the `public/` directory. No CDN dependencies.

### Environment Variables

- `LILYPOND_SERVICE_URL` (secret) — base URL of the external LilyPond service.
- `LILYPOND_API_KEY` (secret) — bearer token for the external service.
- `LILYPOND_TIMEOUT_MS` (var, default 30000) — timeout for external service calls.

### Paths

- `/etude` - GET — main etude generation page
- `/etude` - POST — generate etude
- These replace the '/private' in the base auth app
